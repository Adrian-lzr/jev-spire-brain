# 铁甲战士多打法规则

本项目不把铁甲战士固定成“每回合优先攻击”或单一防守策略。打法配置位于
`config/archetypes.json`，由 `spirebrain/strategy.py` 根据当前卡组信号选择。

## 资料提炼

规则来自项目内的攻略调研与 `docs/CARD_STRATEGY.md`：

- **自适应端口**：没有明确流派信号时，先补输出、防御、运转三端中最弱的一端；不为想象中的流派牺牲当前战斗。
- **力量成长**：先出现力量来源，再提高力量倍数、多段攻击和能量/过牌；第一幕避免没有生存支撑的慢牌。
- **消耗引擎**：`Corruption`、`Feel No Pain`、`Dark Embrace` 等信号出现后，提高消耗、格挡、抽牌和收尾牌的优先级。
- **格挡堆叠**：先建立格挡产量，再考虑 `Barricade`、`Entrench`、`Body Slam` 等转化，不把单张 `Barricade` 当作即时防御。
- **自伤收益**：只有 `Rupture`/`Blood for Blood` 等收益信号出现并且生命预算允许时，才提高自伤牌价值。
- **异常牌转化**：`Evolve`/`Fire Breathing` 在线后，才提高会塞入异常牌的卡牌价值，并保留过牌处理污染。

## 运行时约束

打法是软策略，不是硬锁定：至少达到配置的信号数量才会提交；多个打法接近时回到自适应；生命低于 35% 时强制回到生存优先。硬规则、合法性和当前战斗威胁始终高于打法偏好。

当前选择会同时进入 JEV 的完整运行状态和 GPT 的战略提示。GPT 可以重新规划目标，但只能从本地合法候选中选择；本地卡牌评分会给已确认打法的核心/配合牌小幅加权，并保留“解决当前短板”的优先级。
