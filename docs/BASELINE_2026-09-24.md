## 合成回放与指标

输入：`tests/fixtures/metrics/decision_trace.jsonl` 和
`tests/fixtures/replay/advisor_states.json`，均标记为 `synthetic`。

- 4 条轨迹记录，1 个 run，2 个 state，2 个 decision；
- 1 次 provider 请求；请求 p50/p95 为 120 ms；决策 p50 为 112.5 ms，p95 为 141.75 ms；
- 合法动作率 0.5（一个战斗建议合法，一个商店动作因金币不足被过滤）；
- fallback 率 0.5，原因是 `rule_constraint`；
- `unobserved` 比例 1.0，真实结果为 `unknown`；
- replay 产生 3 个 advise 轮询命令，全部属于 `wait/state`，无非法执行动作。

这些数字只验证事件契约、时序和合法性。合成伤害、采纳率、抽牌数量、每幕
HP 或模拟结果都不是胜率证据；没有真实玩家结果时不推断胜率提升。

## 记录到的现有行为

当前回放覆盖 combat 的建议与安全轮询、shop 的金币约束和规则 fallback，以及
建议事件的状态/来源字段。`DecisionFeed` 的事件 vocabulary 仍包括
`run_state`、`decision`、`advice`、`outcome`、`run_end`、`agent_state`；当状态
无法建模时面板显示 unavailable，而不是发送执行命令。地图、事件、火堆和真实
游戏内 Java 面板仍需要真机回放确认，不能用本报告替代。

## 环境适配与 fixture

`spirebrain.environment.EnvironmentAdapter` 统一承载 `LOCALAPPDATA`、
`APPDATA`、`STS_GAME_DIR` 和可选 Steam 根目录。`gamedata`、doctor 与
ModTheSpire 配置路径接受显式 adapter；默认调用仍读取系统环境。卡牌名称和
效果测试使用 `tests/fixtures/gamedata/localization.json`，不读取本机
`desktop-1.0.jar`。
